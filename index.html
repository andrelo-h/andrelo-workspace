How to host your business workspace on GitHub Pages

Complete guide · Zero cost · Estimated time: 45–60 minutes · No prior experience required

What you are building

You are taking the single workspace.html file and hosting it as a real website on GitHub Pages — a free hosting service that GitHub provides to every account. The result is a personal URL you can open from any browser, on any device, at any time.

Phase 1Install tools
Phase 2Set up project
Phase 3Push to GitHub
Phase 4Go live

When you finish this guide you will have:

  • A live URL like yourname.github.io/workspace that you can bookmark
  • Your workspace accessible from your phone, your work computer, or any browser
  • A simple update workflow — edit the file, run two commands, changes go live in under a minute
  • Full version history of every change you ever make
  • Zero ongoing cost — GitHub Pages is permanently free for public repositories
ℹ

Your data stays in your browser. The HTML file is just the interface — the app's code and structure. Your actual data (projects, clients, ideas) is stored in your browser's local storage on each device you use it from. The guide includes a section on backing up that data.

Phase 1 — Install your tools

Step 1: Install Git

Git is how your local files connect to GitHub. It is a command-line tool, meaning you interact with it by typing short commands into a terminal window. You will learn exactly four Git commands to manage this project.

Download Git

Go to git-scm.com/downloads and click the download button for your operating system. The site detects your OS automatically.

  • Windows: download the .exe installer
  • Mac: the recommended method is installing via Homebrew (explained below), but there is also a direct download if you prefer

Install Git on Windows

Run the downloaded .exe file. The installer has many screens — use these settings:

  • When asked about the default editor, select Visual Studio Code from the dropdown (you will install this next)
  • When asked about PATH environment, select "Git from the command line and also from 3rd-party software"
  • Leave all other settings at their defaults and click Next through the rest

After installation, open the Start menu, search for Git Bash, and open it. You should see a terminal window with a prompt. Type the command below and press Enter — if it prints a version number, Git is installed correctly.

Git Bash (Windows)
git --version

Install Git on Mac

Open the Terminal app. You can find it by pressing Command + Space and typing "Terminal". Then run:

Terminal (Mac)
xcode-select --install

A dialog will appear asking you to install the Command Line Developer Tools. Click Install. This takes a few minutes. Git is included in this package. After it finishes, verify with:

Terminal (Mac)
git --version

You should see something like git version 2.39.0. The exact number does not matter.

Configure Git with your name and email

Git needs to know who you are so it can label your commits (saved changes). Run these two commands, replacing the example name and email with your own. Use the same email you will use for your GitHub account.

Terminal / Git Bash
git config --global user.name "Your Name"
git config --global user.email "you@email.com"

These commands produce no output when they succeed. That is normal — silence means it worked.

Step 2: Install VS Code

Download and install VS Code

Go to code.visualstudio.com and click the large download button. The site detects your operating system automatically.

  • Windows: run the .exe installer. On the "Select Additional Tasks" screen, check "Add to PATH" and "Open with Code" context menu options. These make VS Code much easier to use from the terminal.
  • Mac: open the .dmg file, drag VS Code to your Applications folder. Then open VS Code, press Command + Shift + P, type "shell command", and select "Shell Command: Install 'code' command in PATH". This lets you open VS Code from the terminal.

Install the Live Server extension

This extension lets you preview your HTML file in a browser that automatically refreshes when you save changes. It is the fastest way to test edits.

  • Open VS Code
  • Click the Extensions icon in the left sidebar (it looks like four squares)
  • In the search box, type Live Server
  • The top result should be by Ritwick Dey with over 30 million downloads
  • Click Install

After installing, you will see a "Go Live" button in the bottom-right corner of VS Code whenever you have an HTML file open.

Step 3: Create your GitHub account

Sign up at github.com

Go to github.com and click Sign up. Choose your username carefully — it will appear in your website URL. Use something professional since this profile will serve as part of your developer portfolio.

  • Recommended username format: firstname-lastname or firstnamelastname
  • Avoid numbers, underscores, or words unrelated to your professional identity
  • Your workspace URL will be: yourusername.github.io/workspace

Choose the Free plan — it includes unlimited public repositories and GitHub Pages hosting.

Set up SSH authentication (recommended)

SSH is a secure way for Git to communicate with GitHub without typing your password every time. This is the professional standard and worth setting up once.

In your terminal, run:

Terminal / Git Bash
ssh-keygen -t ed25519 -C "you@email.com"

Press Enter three times to accept all defaults (no passphrase is fine for a personal machine). Then run:

Terminal / Git Bash
# Mac
cat ~/.ssh/id_ed25519.pub

# Windows (Git Bash)
cat ~/.ssh/id_ed25519.pub

This prints a long string starting with ssh-ed25519. Copy the entire output. Then:

  1. Go to github.com → Settings → SSH and GPG keys
  2. Click New SSH key
  3. Title: My laptop (or whatever describes your machine)
  4. Paste the key into the Key field
  5. Click Add SSH key

Test that it worked:

Terminal / Git Bash
ssh -T git@github.com

You should see: Hi yourusername! You've successfully authenticated...

Phase 2 — Set up your project

Step 4: Set up your project folder

Create the project directory

Create a dedicated folder for this project on your computer. This folder will become a Git repository — a tracked, version-controlled directory. Put it somewhere logical in your file system.

Terminal / Git Bash
# Navigate to where you keep your projects
# Replace with your actual path — for example:
cd Documents

# Create the folder
mkdir workspace

# Enter the folder
cd workspace

Your terminal prompt should now show you are inside the workspace folder.

Initialize a Git repository

This turns the folder into a Git-tracked project. Run this command from inside the workspace folder:

Terminal / Git Bash
git init

You will see: Initialized empty Git repository in .../workspace/.git/

A hidden .git folder now exists inside your directory. This is Git's database — do not delete or edit it.

Step 5: Save your HTML file

Place the workspace.html file in the project folder

Take the workspace.html file you downloaded from Claude and copy it into the workspace folder you just created.

Then rename it to index.html. This is critical — GitHub Pages looks for a file named exactly index.html to serve as the homepage of your site.

Terminal / Git Bash
# If you placed workspace.html in the folder, rename it:
# Mac / Git Bash on Windows:
mv workspace.html index.html

Alternatively, rename the file manually through your file explorer — just make sure it is called index.html exactly (lowercase, no spaces).

Verify your folder structure

Your workspace folder should contain exactly one file:

Terminal / Git Bash
ls

Output should be: index.html

That is your entire project. One file. Clean and simple.

Step 6: Open the project in VS Code

Open VS Code in the project folder

From inside the workspace folder in your terminal, run:

Terminal / Git Bash
code .

The dot . means "open the current folder." VS Code will open with your project loaded in the sidebar.

You can also open VS Code manually and use File → Open Folder to navigate to your workspace folder.

Explore the VS Code interface

The key areas you will use:

  • Explorer (left sidebar): shows your files. Click index.html to open it in the editor.
  • Editor (center): where you read and edit your code.
  • Terminal (bottom): open with Ctrl + ` (backtick) on Windows or Control + ` on Mac. This is where you run Git commands without leaving VS Code.
  • Source Control (left sidebar, branch icon): shows your Git status visually.
  • Go Live button (bottom-right): the Live Server button that previews your file in a browser.

Step 7: Test your workspace locally

Launch Live Server

With index.html open in the editor:

  • Click the Go Live button in the bottom-right corner of VS Code
  • Your default browser will open with your workspace running at http://127.0.0.1:5500/index.html

This is a local server running on your machine. No internet connection required. Every time you save index.html in VS Code (Ctrl+S / Command+S), the browser will automatically refresh.

Verify everything works

Walk through each section of the workspace and confirm the following:

  • Dashboard loads and shows zero values
  • You can add a priority task and it appears in the list
  • You can add a project and it appears in the Projects tab
  • You can add a client and it appears in the Clients tab
  • Close the browser tab and reopen it — your data should still be there (localStorage is working)
✓

If everything works locally, you are ready to deploy. If something looks broken, let me know and we can fix it before deploying.

Phase 3 — Connect to GitHub

Step 8: Create a GitHub repository

Create a new repository on GitHub

  1. Go to github.com and log in
  2. Click the + icon in the top-right corner → New repository
  3. Fill in the form:
    • Repository name: workspace (this becomes part of your URL)
    • Description: Personal business workspace (optional)
    • Visibility: Public — GitHub Pages requires public repositories on the free plan
    • Do NOT check "Add a README file"
    • Do NOT add a .gitignore or license
  4. Click Create repository

Copy your repository URL

After creating the repository, GitHub shows you a page with setup instructions. Find the SSH URL at the top — it looks like:

Your repository URL
git@github.com:yourusername/workspace.git

Make sure you are looking at the SSH tab (not HTTPS) since you set up SSH authentication in Step 3. Copy this URL — you will use it in the next step.

Step 9: Connect your local folder to GitHub

Link the local repository to GitHub

In your terminal (either in VS Code or Git Bash), make sure you are inside the workspace folder. Then run:

Terminal / Git Bash
# Connect your local folder to the GitHub repository
# Replace yourusername with your actual GitHub username
git remote add origin git@github.com:yourusername/workspace.git

# Set the default branch name to "main"
git branch -M main

No output means it worked correctly.

Step 10: Push your code to GitHub

Pushing means sending your local files up to GitHub. You do this in three commands that you will use every time you update your workspace in the future.

Stage, commit, and push

Terminal / Git Bash
# Stage all files (tells Git which files to include in the commit)
git add .

# Commit — save a snapshot of your code with a description
git commit -m "Initial commit: business workspace"

# Push — send your code to GitHub
git push -u origin main

The -u origin main flag on the first push sets the default remote branch. After the first push, you only need to type git push for future updates.

Verify on GitHub

Go to github.com/yourusername/workspace in your browser. You should see your index.html file listed in the repository. If you see it, your code is on GitHub.

Phase 4 — Deploy to GitHub Pages

Step 11: Enable GitHub Pages

Turn on GitHub Pages in your repository settings

  1. In your repository on GitHub, click the Settings tab (top navigation, rightmost option)
  2. In the left sidebar, click Pages
  3. Under Source, click the dropdown that says "None" and select Deploy from a branch
  4. Under Branch, select main from the dropdown
  5. Leave the folder set to / (root)
  6. Click Save

Wait for deployment

GitHub Pages takes 1–5 minutes to deploy for the first time. You can watch the progress:

  • Go to the Actions tab of your repository
  • You will see a workflow called "pages build and deployment" running
  • A yellow circle means it is in progress
  • A green checkmark means it is complete and your site is live
⚠

Do not refresh the Settings → Pages screen too quickly. Wait for the Actions workflow to complete. The URL will appear on the Pages settings page once deployment finishes.

Step 12: Verify your site is live

Open your live URL

After the deployment workflow completes, go back to Settings → Pages. You will see a green banner that says:

Your live URL
Your site is live at https://yourusername.github.io/workspace

Click the URL. Your workspace should open in the browser — running live on the internet, accessible from any device.

Bookmark this URL. Add it to your phone's home screen. Share it with no one (it is public but obscure — no one will find it unless you share the link).

Add to your phone's home screen

This turns your workspace into a pseudo-app on your phone:

  • iPhone (Safari): open the URL in Safari → tap the Share button → tap "Add to Home Screen" → tap Add
  • Android (Chrome): open the URL in Chrome → tap the three-dot menu → tap "Add to Home screen" → tap Add

The workspace will appear as an icon on your home screen and open in full-screen mode when tapped.

ℹ

Remember: data is stored per browser. Your phone and your laptop have separate localStorage. Use the Export backup button on each device to keep your data in sync, or enter data on one primary device and treat others as read-only.

Step 13: Custom domain (optional)

If you own a domain name (for example yourdomain.com), you can make your workspace available at a cleaner URL like workspace.yourdomain.com. This is entirely optional and costs nothing beyond your domain registration.

Point a subdomain at GitHub Pages

  1. In your domain registrar's DNS settings, add a CNAME record:
    • Name: workspace (or whatever subdomain you want)
    • Value: yourusername.github.io
    • TTL: 3600 (or Auto)
  2. In your GitHub repository, go to Settings → Pages → Custom domain
  3. Enter workspace.yourdomain.com and click Save
  4. Create a file called CNAME (no extension) in your project with just the domain on one line
  5. Push that file to GitHub

DNS changes can take up to 24 hours to propagate. GitHub will also automatically issue an SSL certificate (HTTPS) once it sees your domain.

Maintenance and ongoing use

How to update your workspace

Every time you want to add a new feature, fix something, or change the design of your workspace, this is the workflow:

The three-command update cycle

  1. Open VS Code and edit index.html
  2. Preview your changes using Live Server
  3. When you are satisfied, open the terminal and run:
Terminal / VS Code terminal
# Stage your changes
git add .

# Commit with a description of what you changed
git commit -m "Add export to CSV feature"

# Push to GitHub (site updates in 1-2 minutes)
git push

Your live site will reflect the changes within one to two minutes. You can watch the deployment in the Actions tab of your GitHub repository.

Git commandWhat it doesWhen to use it
git add .Stages all changed files for the next commitEvery time before committing
git commit -m "message"Saves a labeled snapshot of your staged changesAfter staging, before pushing
git pushSends committed changes to GitHubAfter committing, to go live
git statusShows which files have changed since last commitAny time you want to check
git log --onelineShows recent commit historyWhen you want to review changes

Backing up your workspace data

Your workspace data — projects, clients, content ideas, schedule — lives in your browser's localStorage. The HTML file on GitHub Pages is just the code shell. Understand this distinction clearly:

What lives on GitHubWhat lives in your browser
The HTML file (code + structure)All your projects, clients, ideas, priorities
Backed up automatically with every pushOnly backed up when you use the Export button
Accessible from any deviceOnly on the specific browser you entered it in
⚠

Export your data weekly. Click the "Export backup" button in the bottom-left sidebar of your workspace. Save the downloaded JSON file to a cloud storage service like Google Drive or Dropbox. If you ever clear your browser history or switch computers, you will lose your data without this backup.

When your data needs grow: migrate to a database

localStorage is sufficient when you are the only user on one or two devices. When you want real sync across devices, you have two upgrade paths:

  • Supabase (free tier): a hosted PostgreSQL database with a JavaScript SDK. You can add it to your existing HTML file. Free tier gives you 500MB and 2GB bandwidth per month — more than enough for personal use indefinitely.
  • Firebase Firestore (free tier): Google's real-time database. Also free for personal scale. Slightly easier to set up than Supabase for a simple single-user app.

Both are a meaningful technical step up from what you have now, but they are natural next projects once you have outgrown localStorage. Come back to this when you feel ready to level up the tech.

Troubleshooting

Site not loading after enabling Pages

Wait five minutes and hard-refresh the browser (Ctrl+Shift+R on Windows, Command+Shift+R on Mac). Check the Actions tab in your GitHub repository — if the workflow shows a red X, click it to see the error message.

Page shows a 404 error

This almost always means the file is not named exactly index.html (all lowercase). Check your repository on GitHub and confirm the filename. If it is Index.html or workspace.html, rename it and push again.

Git push is rejected

Terminal / Git Bash
# If you get a rejection error, pull first then push
git pull origin main --rebase
git push

SSH authentication fails

Run ssh -T git@github.com to test your connection. If it fails, go back to Step 3.2 and verify your SSH key is added to your GitHub account correctly. On Windows, make sure you are using Git Bash, not PowerShell or Command Prompt, for SSH commands.

VS Code terminal does not recognize git

On Windows, set the default terminal in VS Code to Git Bash: press Ctrl+Shift+P, type "Select Default Profile", and choose Git Bash. Close and reopen the terminal.

My data disappeared

localStorage data is browser-specific and can be cleared if you clear your browser history and check "Cookies and site data." Always use the Export backup button before clearing your browser. If you have a backup JSON file, you can re-import data by adding an import feature — ask Claude to add an import button to your workspace HTML.
